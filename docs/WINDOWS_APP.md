# Windows 앱 · 내부 검토용 0.3.0

Windows x64 설치형 앱입니다. 사용자 PC에 Python, Rust, Git, GPU 드라이버를 따로 설치할 필요가
없도록 Python 실행 엔진을 설치 파일에 포함합니다. 학습용 CUDA와 LLaMA-Factory는 RunPod 또는 GPU 서버에 설치합니다.
WebView2가 없으면 설치 중 Microsoft 런타임 다운로드가 필요합니다.
현재 설치 파일은 코드 서명하지 않은 내부 검토용입니다.

> **개발 브랜치 안내:** 아래 “GPU 서버(SSH 직접 실행)”와 MLflow “인증 없음”은 개발 브랜치
> (codex/general-training-workflows)에 구현되어 있으며 배포된 0.3.0 설치 파일에는 포함되어 있지 않습니다.
> 설치 파일 검증은 별도 작업(Task 11)에서 진행합니다. 실제 SSH 서버·GPU·Tauri/WebView2 셸·Windows 자격 증명
> 저장소에서의 시험은 아직 하지 않았으며, 화면은 가짜 연결로 시험했습니다.

## 처음 사용

1. 제공받은 LLM Tuning Factory_0.3.0_x64-setup.exe를 설치합니다.
2. **연결 설정**에서 RunPod API 키, 배정받은 Pod ID, SSH 개인키 파일과 서버 지문을 입력합니다.
   SSH 지문은 관리자가 신뢰할 수 있는 경로로 확인해 전달해야 합니다. 접속 시 관측한 값을 자동 승인하지 않습니다.
3. MLflow 주소와 OIDC 인증값 또는 별도 토큰을 입력하고 **연결 정보 저장**, **연결 검사**를 누릅니다.
   기존 공용 주소가 기본값입니다. 인증값은 Windows 자격 증명 저장소에 저장되며 화면에 다시 반환하지 않습니다.
   .env를 직접 편집할 필요가 없습니다. SSH 개인키는 원래 파일 위치에 남습니다.
4. RunPod에서 **본인에게 배정된 Pod**를 시작합니다. /workspace에 Network Volume이 연결되고
   public TCP SSH가 제공되어야 합니다. 앱은 Pod를 자동 생성·시작·정지·삭제하지 않습니다.
5. **학습 환경 준비**를 확인 후 실행합니다. 실행 중인 Pod에 앱 전용 Python 3.12 환경과 해시로 고정한
   의존성, 현재 앱과 일치하는 작업 패키지를 설치합니다. 최초 설치는 수 분 이상 걸릴 수 있으며
   GPU 요금과 저장·전송 비용이 발생할 수 있습니다. Python3/pip/flock, C 컴파일러(cc/gcc) 및 외부 패키지 다운로드가
   가능한 Pod가 필요합니다. 시스템 Python이나 기존 다른 학습 환경을 변경하지 않습니다.
   CUDA devel 계열 이미지를 권장합니다. CUDA가 보여도 C 컴파일러가 없으면 Triton 학습 초기화가
   실패하므로 앱이 준비 단계에서 차단합니다. 컴파일러 설치는 Pod 관리자가 수행합니다.
6. **GPU 정보 → 학습 설정에 적용**으로 실제 GPU 종류·수·현재 요금을 가져옵니다.

기존 Pod를 시작할 때 `There are not enough free GPUs on the host machine` 오류가 나면 해당 호스트의
GPU가 부족한 상태입니다. 앱을 다시 설치해도 해결되지 않습니다. 관리자가 같은 데이터센터의 가용 GPU와
저장 볼륨을 확인해 별도 Pod를 준비한 뒤 새 Pod ID와 검증된 SSH 지문을 입력합니다. 기존 작업의 결과
회수는 원래 실행한 Pod ID를 확인하므로, 연결을 바꾸는 것만으로 다른 Pod에서 이어받지는 않습니다.

### GPU 서버(SSH 직접 실행)로 연결하기

RunPod 대신 BOP 같은 기관 Linux GPU 서버를 쓰는 경우 2번과 4~6번 대신 아래 순서를 따릅니다.
RunPod API 키, Pod ID, /workspace 네트워크 볼륨은 필요하지 않습니다. 앱은 서버를 켜거나 끄지 않습니다.

1. 관리자에게 받을 정보: 서버 주소와 SSH 포트, 접속 계정, 관리자가 신뢰할 수 있는 경로로 확인한 서버
   **SHA256 지문**(ED25519 호스트 키 지문을 요청하세요), 내가 쓸 수 있는 GPU, 쓰기 가능한 작업 폴더(절대 경로,
   예: /home/USER/factory). SSH 키 쌍은 직접 만들고 공개키 등록을 관리자에게 요청합니다. 개인키는 절대 전달받거나
   보내지 않습니다. 개인키는 OpenSSH 형식의 암호(passphrase) 없는 파일이어야 하며 SSH 에이전트는 사용하지 않습니다.
   PuTTY .ppk 경로는 저장 시 거부되므로 OpenSSH 형식으로 변환하세요. 접속 시 관측한 지문은 자동으로 신뢰하지 않습니다.
   root 계정은 필요하지 않습니다. 작업 폴더 경로에는 영문자·숫자와 `_ . / -`만 쓸 수 있습니다(한글 불가).
2. **연결 설정**의 **GPU 연결 대상**에서 “GPU 서버 · SSH 직접 실행 (BOP 등)”을 고릅니다.
   **서버 주소**, **SSH 포트**, **접속 계정**, **SSH 개인키 파일**(**파일 찾기**로 선택, 키 내용은 붙여 넣지 않음),
   **SSH 서버 지문**, **작업 폴더 · 절대 경로**, **시간당 비용 (USD) · 서버 전체**를 입력하고 저장합니다.
   비용은 직접 입력하는 값이며 클라우드 요금 조회 결과가 아닙니다. 내부 서버는 0을 입력할 수 있습니다.
3. **GPU 학습 환경** 카드의 **GPU 목록 조회**로 서버의 NVIDIA GPU를 읽고, 사용할 GPU를 **정확히 1개** 체크한 뒤
   **GPU 선택 저장**을 누릅니다. 현재 앱은 작업당 GPU 1개만 허용하며 더 많이 저장하면 거부됩니다. 이미 저장된 선택이
   1개를 넘으면 환경 확인·준비 등 서버 동작이 비활성화되고 설정 단계가 완료되지 않은 것으로 표시되며,
   **데이터 전송에 동의하고 학습 시작**도 비활성화되고 정책 안내 메시지가 표시됩니다. GPU는 번호가 아닌 UUID로 저장됩니다. 조회만으로는 파일을 만들거나 설치하지 않습니다.
4. **환경 확인**은 작업 폴더의 학습 환경이 현재 앱과 맞는지 읽기 전용으로 확인합니다.
   **학습 환경 준비**는 승인 창에서 서버·작업 폴더·선택 GPU를 확인한 뒤 실행합니다. 작업 폴더 아래에
   앱 전용 Python 환경, 캐시를 만들며 데이터는 전송하지 않습니다. sudo·apt를 사용하지 않으며 서버 기본 Python을 바꾸지 않습니다.
   다른 사용자 환경도 변경하지 않습니다. 준비에는 서버에서 PyPI 또는 설정된 pip/uv 미러에 접속할 수 있어야 합니다
   (Python 3.12는 없을 때만 내려받습니다). Hugging Face 모델 다운로드만 작업 폴더의 hf-cache를 미리 채워 피할 수 있습니다. 최초 준비는 다운로드 때문에 시간이 걸립니다.
5. 학습 설정으로 이동하기 전에 **GPU 정보 → 학습 설정에 적용**을 눌러 선택한 GPU 종류·수와 입력한 시간당 비용을 반영합니다.
6. **실행 계획 확인**의 목적지 줄(“GPU 서버: 주소 · 선택 GPU n개 · GPU: 종류”)이 의도한 서버인지 확인합니다.
   서버 설정이 불완전하거나 올바르지 않거나 GPU 선택이 없어 계획에 목적지 해시가 없으면 시작 버튼이 비활성화되고
   사유가 표시됩니다. 설정을 바꿔 저장하면 기존 계획이 사라지므로 계획을 다시 확인합니다. 계획 이후 바뀐 설정으로
   제출하면 “연결 설정이 실행 계획 이후 바뀌었습니다. 실행 계획을 다시 확인하세요.”라며 거부됩니다.
   **실행 관리**의 **실행 위치** 열에서 작업별 목적지(“GPU 서버 · 주소” 또는 “RunPod”)를 볼 수 있습니다.

서버 요구 조건: Linux, 접속 계정이 읽을 수 있는 /etc/machine-id, nvidia-smi로 보이는 NVIDIA GPU(MIG 분할은 거부하며 MIG GPU가 하나라도 있으면 조회 전체가 실패),
pip가 있는 python3, flock, C 컴파일러(cc). 작업 폴더는 쓰기 가능해야 하며 경로와 상위 폴더(예: /home)가 심볼릭 링크이면 안 되므로 실제(resolved) 경로를 입력합니다.
없는 도구는 설치하지 않고 관리자에게 요청하라는 메시지를 표시합니다.

**환경 준비 예약.** 준비 중 연결이 끊기는 등 종료를 확인하지 못하면 예약이 남아 같은 서버의 준비·학습을 막습니다.
**준비 예약 확인**으로 목록을 보고, ‘종료 확인 필요’ 항목과 앱이 강제 종료되어 ‘준비 중’으로 남은 항목은
**원격 준비 종료 확인 · 예약 해제**로 해제합니다. ‘준비 중’ 항목은 실제로 아직 실행 중일 수 있으므로 강한 경고가 표시됩니다.
해제 전에 서버에서 준비 프로세스가 끝났는지 직접 확인해야 하며 승인 창에서 이를 확인합니다. 저장된 서버 설정과
다른 서버로 만든 예약은 그 설정으로 바꾼 뒤 해제합니다.

학습 단계와 S3 연결의 상세 절차는 [학습·스토리지 안내](TRAINING_AND_STORAGE.md)를 확인하세요.

### MLflow 인증 없음

로컬이나 내부망의 인증 없는 MLflow 서버는 **MLflow 서버 주소**에 주소(예: `http://127.0.0.1:5000`)를 넣고
**인증 방식**에서 “인증 없음 · 로컬·내부 서버”를 고릅니다. OIDC·토큰 입력란이 숨겨지며 앱은 저장된 인증값을
지우지 않고 사용하지도 않습니다. 다른 방식으로 되돌리면 저장된 값을 다시 씁니다. 토큰이나 OIDC 인증값(주소와 시크릿 모두 있을 때)을
쓰면 데스크톱 앱과 CLI 모두 HTTPS 주소만 허용하고 HTTP는 인증 없음에서만 허용됩니다. HTTP 산출물 위치(서버가 실행별로 정한 위치 포함)도 거부됩니다. OIDC 주소만 있고 시크릿이 없으면 앱은 시작되지만 MLflow 동작이 아래 오류로 실패합니다. 인증값이 있으면 로컬 `file:`·`sqlite:` 저장소 주소도 거부되므로 로컬 저장소는 인증값을 비우고 사용하세요. **인증 없음은 서버에 접근할 수 있는 누구나
실행 기록을 볼 수 있으므로 신뢰할 수 있는 로컬·내부망에서만 사용하세요.** 로컬 서버 실행 예는
[운영 안내](OPERATIONS.md)를 확인하세요. **연결 검사 결과**의 MLflow 조회 줄은 “확인됨 · 인증 없음”처럼 방식과 함께 표시되며,
GPU 서버 연결에서는 “GPU 서버” 줄에 주소와 GPU 요약, “실제 GPU 학습” 줄에 아직 확인하지 않았음이 표시됩니다.
OIDC를 선택했는데 클라이언트 인증값이 없으면 “OIDC 인증을 선택했지만 클라이언트 인증값이 없습니다. 인증값을 입력하거나 ‘인증 없음’을 선택하세요.”라는 오류가 표시됩니다.

## 학습

1. **데이터**에서 JSON/JSONL 파일을 선택하고 ID와 버전을 지정합니다. Alpaca 또는 ShareGPT 형식이 필요합니다.
   등록 시 데이터 형식·해시를 검사하고 PC에 불변 사본을 보관합니다. GPU 전송 허용은 별도로 선택합니다.
   다른 데이터로 바꾸려면 새 버전을 등록합니다.
2. **학습 설정**에서 논문 추출·실험노트 생성·업무 분류 예제 또는 저장한 업무 설정을 선택합니다.
   업무 AI ID와 기반 모델은 별개입니다. 데이터 버전을 선택하고 기본 학습 옵션을 조정합니다.
   앱 기본값은 epoch 기준 학습이며, 예제 CLI의 2-step smoke 설정을 그대로 사용하지 않습니다.
3. 최신 모델은 **Hugging Face 모델 추가**에서 검색하거나 모델 ID를 입력해 확인·추가합니다.
   구조에 맞는 템플릿과 고정 commit을 적용하며 지원하지 않는 모델은 이유를 표시합니다.
   기본 목록에서 기반 모델을 바꾸면 **선택한 모델 버전 확인·고정**을 누릅니다. Hugging Face의 공개 메타데이터에서
   정확한 commit을 조회합니다. 모델 파일은 이 단계에서 내려받지 않습니다. 최초에는 공개 Qwen을 권장합니다.
   Llama 같은 접근 제한 모델은 이용 승인과 GPU에 준비한 캐시가 필요합니다. 연결 화면의 HF 읽기 토큰은
   메타데이터 조회용으로만 저장하며 GPU에는 전달하지 않습니다.
4. 업무 지표가 필요하면 **별도 검증 데이터**와 평가 방식을 선택합니다. 검증 데이터 없이 학습 완료만
   확인한 결과는 업무 품질 점수가 아닙니다. 학습 데이터와 검증 데이터가 중복되지 않도록 준비합니다. RM은 preference 검증 데이터와 reward 평가를 선택합니다.
5. **실행 계획 확인**에서 확정된 설정, 데이터, 최대 시간 기준 예상 GPU 비용을 확인합니다.
   기본 앱 정책은 GPU 1개·4시간·예상 비용 $5 이하입니다. 기존 Pod 전체 청구에 대한 강제 한도가 아닙니다.
6. **데이터 전송에 동의하고 학습 시작**을 눌러 실제 전송과 실행을 승인합니다.
   이후 데이터 전송 → LLaMA-Factory 학습 → 선택한 생성 평가 → 산출물 회수 → MLflow 저장을 실행합니다.
   기존 Pod는 끝나도 계속 과금될 수 있으므로 담당자가 상태를 확인하고 정지해야 합니다.

## 실행 관리와 복구

- **실행 관리**에서 상태, 회수된 학습 로그, 원격 실시간 로그와 평가 결과를 봅니다.
- **취소 요청**은 작업 취소를 요청하는 동작이며 원격 종료가 확인되었다는 뜻이 아닙니다.
  로컬 실행기가 연결을 잃었다면 Pod 또는 GPU 서버의 프로세스 상태를 확인해야 합니다.
- 앱 창을 닫아도 이미 시작된 원격 작업은 자체 시간 제한으로 실행됩니다.
  로컬 실행 프로세스도 살아 있으면 회수를 계속하지만 PC 종료 시에는 회수가 중단됩니다.
- 다시 앱을 열고 **연결 끊긴 작업 확인**, 해당 작업 선택, **재연결 · 결과 회수**를 사용합니다.
  마지막 heartbeat 이후 120초가 지나기 전에는 작업이 아직 실행 중으로 보일 수 있습니다.
  원격 작업이 끝나지 않았으면 나중에 회수를 다시 시도합니다. 불확실한 작업의 GPU 잠금은 유지합니다.
- 실제 취소와 체크포인트 회수·해시 검증 이후 체크포인트 이름을 지정해 재개할 수 있습니다.
  앱 버전을 변경하면 기존 명세의 소스 해시와 달라질 수 있으므로 실행 중에는 업데이트하지 마세요.

## 공용 기록 비교

**기록 비교**에서 실험 목록과 실행 기록을 조회하고 두 실행을 선택합니다.
50개씩 불러오며 다음 페이지를 추가할 수 있습니다. 설정과 지표를 나란히 표시하고, 동일 업무·검증 데이터
해시·평가 방식의 완료된 실제 실행에 한해 지표 차이를 계산합니다. 합성 데이터 표시는 유지합니다.
공용 MLflow의 접근 권한은 서버가 관리합니다. 기록 및 산출물에 포함할 수 없는 민감한 데이터는 넣지 마세요.

0.2.3에서는 불러온 기록의 검색·상태 필터, 변경된 설정 표시, 이전 설정으로 새 실험 준비를 제공합니다.
**이 설정으로 새 실험**은 설정만 불러오며 바로 실행하지 않습니다. 이 PC의 데이터 버전을 확인하세요.

## 새 화면과 미리보기

밝은 Linear·Vercel 계열의 작업 화면으로 개편했습니다. Ctrl+K로 페이지를 빠르게 찾을 수 있습니다.
데이터 등록 전에 **샘플 미리보기**로 형식·건수·중복 레코드와 앞 3건을 검사합니다. 미리보기는 32 MiB
이하 파일을 지원하고 긴 내용을 줄여 표시합니다. GPU 전송은 발생하지 않습니다.
학습과 검증에 byte 단위로 같은 스냅샷을 선택하면 실행 계획과 제출 단계에서 차단합니다.
부분 중복이나 의미상 유사한 데이터까지 탐지하는 기능은 아닙니다.

**실행 관리**의 저장된/원격 진행 지표는 LLaMA-Factory의 실제 trainer_log.jsonl을 읽습니다.
원격 지표를 선택하면 실행 관리 화면에서 10초 간격으로 갱신합니다. 손상·미완성 줄과 유한하지 않은
loss를 제외하며 최대 200개 지점을 표시합니다. 기록이 없으면 대기 상태를 보여 줍니다.
표시한 train loss는 업무 품질 점수가 아닙니다. 원격 조회에는 기존 Pod 또는 GPU 서버의 SSH 연결이 필요합니다.
유사 오픈소스 조사와 적용한 개선점은 [조사 기록](OPEN_SOURCE_REVIEW.md)에 정리했습니다.

## 저장 위치와 한계

- 설정·데이터 사본·작업 DB는 사용자 앱 데이터 폴더의 kr.kbiofoundry.tuningfactory 아래에 있습니다.
  이 폴더는 민감한 데이터를 포함할 수 있으므로 공유하거나 저장소에 올리지 않습니다.
- API 키·MLflow 인증값은 Windows 자격 증명 저장소에 있습니다. 앱에서 저장된 인증값을 삭제할 수 있습니다.
  일반 설정 JSON, 학습 명세와 Git에는 저장하지 않습니다.
- Pod 작업과 캐시는 /workspace/factory-desktop 아래에 생성합니다. 소스별 학습 환경을 분리합니다.
- GPU 서버 작업은 지정한 작업 폴더 아래에 생성합니다. 앱 소스 버전별 전용 환경(runtime), 작업 파일(jobs),
  모델 캐시(hf-cache), 내려받은 Python(python), uv 캐시(uv-cache)가 분리되며 pip는 캐시를 쓰지 않습니다. 선택한 GPU UUID만
  CUDA_VISIBLE_DEVICES로 지정합니다. SSH 개인키는 PC의 원래 위치에 남습니다. 서버 주소·포트·계정·지문·키 파일 경로·작업 폴더·
  선택 GPU·비용은 공개 설정으로 저장되지만 키 내용과 인증값은 저장되지 않습니다.
- GPU 서버는 서버당 공장 작업 하나만 실행합니다. RunPod Pod와 서버가 서로 다른 장비인지 증명할 수 없어
  교차 격리합니다. RunPod 작업의 GPU 잠금이 남아 있으면 SSH 작업·준비가 막히고, SSH 작업이나 SSH 준비 예약이 있으면 RunPod 작업과
  RunPod 환경 준비가 막힙니다. RunPod 환경 준비는 예약을 남기지 않으므로 SSH를 막지 않습니다. 같은 서버를 다른 주소로
  등록해도 우회되지 않습니다. 잠금은 이 PC의 로컬 상태에만 있어 다른 PC에서 쓰는 사용자는 막지 못합니다.
- 로그·진행·결과 회수는 작업을 시작한 서버·키·작업 폴더·선택 GPU에 묶입니다. 서버의 다른 GPU 구성이 바뀐
  것은 허용하지만 다른 서버나 설정으로 바꾸면 과거 작업을 이어받지 않습니다. 비용은 입력값 기준이며 실제 사용량 관측이나
  서버의 다른 사용자 작업은 확인하지 않습니다.
- 실제 SSH/BOP 서버·GPU·MLflow 서버·Tauri/WebView2 셸·Windows 자격 증명 저장소 시험은 하지 않았으며 설치 파일 검증은
  Task 11 범위입니다. 서버 기능은 가짜 SSH 응답으로 시험했습니다.
- 여러 PC 사이의 작업 대기열·GPU 잠금은 공유되지 않습니다. 사용자별 Pod 또는 지정 담당자가 필요합니다.
- 대량 데이터 스트리밍, 공통 GPU 배정, 무인 다중 Pod 운영, 서빙은 이번 버전에 포함하지 않습니다.
- PT·SFT·RM·PPO·DPO·KTO와 Full·Freeze·LoRA·QLoRA·OFT를 제공합니다. 단계별 데이터와
  옵션 조합을 검사하며 임의 모델/플러그인을 무조건 허용하지 않습니다. 검토한 텍스트 모델 15개 프로필이 범위입니다.
- S3는 endpoint·버킷·key를 직접 연결해 고정 사본을 PC에 가져옵니다(파일당 32 MiB).
  GPU의 직접 S3 인증이나 무제한 스트리밍은 제공하지 않습니다. S3 키는 Windows 자격 증명 저장소에 보관합니다.
- PPO는 별도 0.9.3 환경과 미리 준비한 보상 모델이 필요합니다. PPO·OFT 재개, Full/Freeze RM 재개,
  OFT의 별도 생성·보상 평가는 upstream 제약으로 차단합니다. PPO 프롬프트는 Alpaca 형식입니다.
- 새 조합은 CPU/UI·격리된 PPO import·로컬 S3 계약을 검사했으며 실제 GPU와 클라우드 S3 검증은 남아 있습니다.
- 실제 H100 + Qwen2.5-0.5B에서 LoRA·실제 4비트 QLoRA·생성·취소·체크포인트 10→100 재개·
  PC 실행기 강제 종료 후 결과 회수·MLflow 산출물 왕복 해시를 확인했습니다.
  다른 모델·대규모 데이터·새 PC 설치·코드 서명은 검증하지 않았습니다.
  [GPU 검증 보고서](GPU_ACCEPTANCE_2026-10-15.md)를 확인하세요.

## 개발·빌드

개발 PC에는 Python 3.12, uv, Node.js, Rust 1.99.0, Windows C++ Build Tools와 WebView2가 필요합니다.

    uv sync --extra dev --extra tracking --locked
    uv run pytest
    uv run ruff check src tests
    uv run python scripts/build_desktop.py
    cd desktop
    npm ci
    npm exec playwright install chromium
    npm test
    cargo test --manifest-path src-tauri/Cargo.toml --locked
    npm run tauri -- build --ci

빌드 결과는 desktop/src-tauri/target/release/bundle/nsis/에 있습니다.
UI 테스트는 가짜 연결을 사용하며 실제 서버·GPU 성공을 증명하지 않습니다.
tests/native-smoke.mjs는 loopback WebView2 debugging을 켠 별도 테스트 앱에서만 수동 실행합니다.
일반 배포 앱은 디버깅 포트를 열지 않습니다. 실제 MLflow 읽기와 정지된 Pod 조회는
scripts/verify_desktop_readonly.py --connection-file ...로 별도 검증할 수 있으며 키를 출력하지 않습니다.
