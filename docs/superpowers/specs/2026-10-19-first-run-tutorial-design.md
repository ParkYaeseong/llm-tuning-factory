# 처음 사용자를 위한 실습형 튜토리얼 — Windows 앱 확장

2026-10-19 사용자 요청: “처음 사용하는 사람은 프로그램 사용이 어려울 수 있을 것 같아 튜토리얼 기능을 넣으려고 해.
이를 통해 사용법 알 수 있게 해줘”. 사용자 선택: 실습형 가이드 투어, Task 6B 직후 현재 화면 기준 구현,
연습 데이터는 실제 작업 공간에 표시해 남김, 자체 모듈 + 화면을 막지 않는 말풍선. 설계 승인: “진행해”.

## 목적과 범위

처음 사용자가 앱 안에서 직접 눌러 보며 연결 → 데이터 → 학습 설정 → 실행 계획의 순서와 각 화면의 의미를 익힌다.
실습은 앱에 포함된 합성 데이터와 dry-run 실행 계획까지만 한다. GPU, 원격 서버, 데이터 전송, 유료 자원은 사용하지 않는다.
연결 단계는 RunPod와 일반 SSH GPU 서버(BOP 등)의 차이와 필요한 정보를 설명만 하며 입력을 요구하지 않는다.
Task 10 화면 개편 이후에도 단계 정의와 화면 표시만 갱신하면 되도록 엔진과 단계 내용을 분리한다.
동영상, 외부 문서 링크 투어, 모의 학습 실행, 진행 위치 이어하기, 다국어는 이번 범위에 포함하지 않는다.

## 순서와 선행 조건

Task 6A 독립 검토 → Task 6B(Windows 일반 GPU 서버 연결 화면) → 이 튜토리얼 순서로 구현한다.
연결 단계의 말풍선은 Task 6B가 만든 연결 대상 선택·SSH 서버 필드·GPU 선택 요소를 가리킨다.
Task 10은 화면을 바꿀 때 `tutorial-steps.ts`와 `data-tour` 표시를 함께 갱신해야 하며, 계약 시험이 누락을 잡는다.

## 사용자 흐름

**시작**
- 완료·닫음 기록이 없으면 작업 공간 상단에 “처음 사용하시나요? 약 5분 실습 튜토리얼” 카드와
  [튜토리얼 시작]·[다음에 하기]를 표시한다. 화면을 막는 팝업은 쓰지 않는다. [다음에 하기]는 닫음으로 기록한다.
- 사이드바 하단 **튜토리얼** 버튼과 Ctrl+K의 “튜토리얼” 항목으로 언제든 처음부터 다시 시작한다.
- 투어 중 다른 화면으로 이동해도 투어는 유지한다. 현재 단계 화면이 아니면 말풍선에 [이 단계로 이동]을 표시한다.

**단계** — 설명: [다음]으로 진행. 실습: 완료 조건을 만족해야 [다음]이 활성화되며, 언제든 [건너뛰기]로 넘어갈 수 있다.
모든 단계에 [이전]과 [그만하기]가 있다. 건너뛴 실습 단계는 기록만 하고 이후 단계는 각자의 완료 조건으로 판단한다.

| # | id | 화면 | 내용 | 종류 | 완료 조건 |
|---|---|---|---|---|---|
| 1 | `welcome` | 작업 공간 | 사이드바 구성과 ‘시작하기’ 체크리스트 | 설명 | — |
| 2 | `connection-provider` | 연결 설정 | RunPod(배정 Pod)와 GPU 서버(BOP 등 SSH 직접 실행)의 차이와 선택 기준 | 설명 | — |
| 3 | `connection-fields` | 연결 설정 | 방식별 필요 정보와 받는 곳. SSH 지문은 관리자에게 받은 값만 사용. 지금 입력하지 않아도 됨 | 설명 | — |
| 4 | `connection-runtime` | 연결 설정 | 환경 확인/준비, GPU 선택의 의미와 비용 발생 가능성 | 설명 | — |
| 5 | `data-preview` | 데이터 | [연습 샘플 채우기]로 양식 자동 입력 후 사용자가 [샘플 미리보기] | 실습 | 미리보기 결과의 행 수·형식이 샘플과 일치 |
| 6 | `data-register` | 데이터 | 사용자가 [검사하고 등록]. 이미 등록되어 있으면 그대로 사용 | 실습 | 카탈로그에 `tutorial_sample` v1 존재 |
| 7 | `training-dataset` | 학습 설정 | 예제 설정을 불러온 뒤 사용자가 학습 데이터에서 `tutorial_sample · v1` 선택. SFT·LoRA·QLoRA 용어 설명 | 실습 | 설정의 학습 데이터가 `tutorial_sample`/`1` |
| 8 | `training-plan` | 학습 설정 | 사용자가 [실행 계획 확인] | 실습 | 현재 dry-run 계획의 학습 데이터가 `tutorial_sample`/`1` (설정 변경 시 기존처럼 계획 무효화) |
| 9 | `plan-reading` | 학습 설정 | dry-run, 예상 비용, ‘전송 동의 후 시작’의 의미. 연습 데이터는 GPU 전송이 차단되어 실행되지 않음 | 설명 | — |
| 10 | `jobs-history` | 실행 관리 | 학습 후 진행률·로그·결과 회수 위치. 사이드바의 기록 비교로 실행을 비교한다는 설명 포함 | 설명 | — |
| 11 | `finish` | 작업 공간 | 다음 할 일(연결 설정 → 실제 데이터 등록·전송 허용 선택 → 학습)과 [연결 설정으로 이동] | 설명 | — |

5단계의 [연습 샘플 채우기]는 데이터 양식 초안에 내장 샘플 경로, ID `tutorial_sample`, 버전 `1`,
종류 `instruction`, 합성 표시 켬, GPU 전송 끔을 채운다. 등록 버튼은 사용자가 직접 누른다.
7단계 시작 시 기존 저장 설정과 무관하게 `paper_extraction` 예제 설정을 학습 설정 초안으로 불러온다.

**종료**
- [그만하기], Esc, 11단계 완료 중 어느 것이든 완료·닫음으로 기록하고 이후 자동 안내 카드를 표시하지 않는다.
- 투어 시작 시 학습 설정 초안(`state.config`), 실행 계획(`state.plan`), 데이터 양식 초안(`state.datasetDraft`)과
  데이터 미리보기(`state.preview`)를 복사해 두고, 투어가 끝나면 되돌린 뒤 호환성 검사를 다시 실행한다.
  작업 공간에 남는 것은 등록한 연습 데이터 `tutorial_sample` v1 하나다. 학습 설정 프로필은 저장하지 않는다.

## 구조

**프런트엔드** (`desktop/src/`)
- `tutorial.ts` — 투어 엔진. 상태(`active`, `index`, 시작 시점 초안 사본), 말풍선/강조 테두리 DOM,
  단계 이동, 키보드 처리, 완료 기록을 소유한다. 말풍선과 테두리는 `#app` 바깥의 별도 layer에 두고
  `render()` 끝에서 호출하는 `afterRender()`에서 대상 위치를 다시 계산한다. 창 크기 변경·스크롤에도 위치를 갱신한다.
  화면 클릭을 가로채는 backdrop을 두지 않아 입력·파일 선택 등 실습을 막지 않는다.
- `tutorial-steps.ts` — 단계 정의만 담는다:
  `{ id, page, anchor, title, body, kind: "explain" | "practice", done?(state), enter?(context) }`.
  `anchor`는 `[data-tour="..."]` 선택자만 허용한다. `enter`는 5단계 양식 채우기, 7단계 예제 불러오기에만 쓴다.
- `main.ts` — `render()` 끝 `afterRender()` 호출, 사이드바 버튼, Ctrl+K 항목, 안내 카드,
  대상 요소의 `data-tour` 속성만 추가한다. 엔진은 기존 `api()`·`action()`을 통해서만 동작하며 별도 실행 경로를 만들지 않는다.
- 완료·닫음 기록은 WebView `localStorage`의 버전 붙은 키(`tuning-factory.tutorial.v1`)에 저장한다.
  네이티브 설정·Rust 설정 저장은 바꾸지 않는다. 저장소를 쓸 수 없으면 안내 카드만 매번 표시하고 기능은 동작한다.

**백엔드**
- `examples/tutorial_sample.json` — 가상의 연구 업무(시료 ID 추출, 실험노트 요약, 업무 분류) 한국어 Alpaca 합성 예제 8건.
  실제 기관·개인 정보 없음. `scripts/build_desktop.py`가 설치 자산 `assets/examples/`에 복사한다.
- 데스크톱 동작 `tutorial_sample` — 입력 없음. `{path, sha256, rows, dataset_id: "tutorial_sample", version: "1", kind: "instruction"}`를
  반환한다. 파일을 등록하거나 쓰지 않는다. Rust `allowed()` 목록에 이 이름만 추가한다.
- 예약 ID 보호 — `dataset`과 `s3_import`에서 `dataset_id == "tutorial_sample"`이면,
  `dataset`은 파일 SHA256이 내장 샘플과 같고 `synthetic is True`, `export_allowed is not True`, 버전 `1`, 종류 `instruction`인 경우만 허용한다.
  `s3_import`는 이 ID를 항상 거부한다. 같은 샘플의 재등록은 기존 불변 등록 규칙에 따라 같은 레코드로 통과한다.
- 실행 계획은 기존 `plan` 동작을 그대로 쓴다. 제출은 기존 정책의 `dataset export has not been authorized in registry`로 거부된다.

## 오류 처리와 안전

- 대상 요소가 없으면 다음 렌더링에서 다시 찾는다. 그래도 없으면 말풍선을 화면 중앙에 두고
  “이 단계의 화면 요소를 찾지 못했습니다”를 표시한다. 설명 단계는 [다음], 실습 단계는 [건너뛰기]로 넘어간다.
- `state.busy` 동안 말풍선에 처리 중 표시를 하고 [다음]을 잠근다. 미리보기·등록·계획 오류는 기존 오류 알림을 그대로 쓰고,
  투어는 같은 단계에 머물며 다시 시도 안내를 덧붙인다.
- 말풍선 문구는 고정 문자열이다. 동적 값(경로·ID·오류)은 `esc()`로 이스케이프한다.
- 말풍선은 `role="dialog"`, `aria-modal="false"`, 제목 연결, 단계 변경 시 `aria-live` 안내를 갖는다.
  단계가 바뀌면 말풍선 제목으로 포커스를 옮기고, Esc는 확인 없이 종료한다. `prefers-reduced-motion`에서는 이동 애니메이션을 끈다.
- 투어는 연결 검사, 환경 준비, 제출, 자격 증명 저장/삭제, S3 동작을 호출하지 않는다.
- DESIGN.md 규칙을 따른다: 강조색 #5367c8 한 가지, 장식 그림자·그라데이션 없음, 반경 8px, 기본 13px.

## 검증

- Playwright `desktop/tests/tutorial.spec.ts`(기존 mock invoke 방식):
  첫 실행 카드 표시와 [다음에 하기] 후 미표시; 사이드바·Ctrl+K 재시작; 11단계 전체 진행;
  실습 단계는 완료 조건 전 [다음] 비활성이고 [건너뛰기]는 가능; 이미 등록된 샘플이면 6단계 즉시 완료; Esc 종료;
  종료 후 이전 학습 설정·계획 복원; 투어 중 `submit`·`runtime_prepare`·`check`·`settings_save` 호출 0;
  말풍선 포커스와 키보드 조작; 대상이 없을 때 중앙 표시와 건너뛰기.
- 계약 시험: 각 단계의 `anchor`가 그 단계 `page`를 렌더링했을 때 정확히 하나 존재한다.
- Python 시험: `tutorial_sample` 반환값과 파일 해시; 예약 ID의 다른 내용·전송 허용·합성 해제·다른 버전/종류·S3 거부;
  같은 샘플 재등록 통과; 연습 데이터로 계획 성공, 제출 거부.
- `scripts/verify_desktop_package.py`가 설치 자산의 샘플 존재와 해시를 확인한다.
- 마무리: `uv run pytest`, `uv run ruff check src tests`, `npm test`, `npm run build`, Rust 허용 목록 시험.
  실제 GPU·SSH 서버·기관 데이터·설치본 수용은 이번 검증에 포함하지 않으며 설치본 확인은 Task 11에서 한다.
