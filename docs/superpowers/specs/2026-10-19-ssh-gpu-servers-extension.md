# 일반 SSH GPU 서버 지원 — 기존 학습 워크플로 확장

2026-10-19 사용자 요청: “gpu 연결이 pod만 되는데 bop 서버처럼 gpu 서버 있다면 이용할 수 있도록”.
실행 방식 확인: “SSH 접속 후 서버에서 직접 실행”. 기존 승인된 프로젝트/학습 그래프 계획에 추가한다.

## 목적과 범위

Windows 앱과 CLI에서 RunPod와 일반 Linux/NVIDIA GPU 서버를 선택한다.
일반 서버에는 RunPod API 키, Pod ID 또는 /workspace 네트워크 볼륨을 요구하지 않는다.
SSH 주소·포트·사용자·키 파일·검증된 호스트 지문·작업 폴더를 설정한다.
사용자가 배정받은 GPU를 조회하고 선택하여 단일 학습 및 그래프 실행에 같은 인프라 어댑터를 사용한다.
학습 엔진, 데이터 승인, 산출물 회수와 공용 MLflow 기록 규칙은 유지한다.
Docker/Slurm 제출, Windows GPU 원격 실행, 서버 생성/전원 제어는 이번 확장에 포함하지 않는다.

## 접속과 자원 확인

- SSH 키 인증과 기존 호스트 SHA256 지문 검증을 재사용한다. 접속 사용자 root를 강제하지 않는다.
- 서버에서 Linux, Python 실행 가능 여부, NVIDIA GPU UUID/이름/메모리와 필요한 도구를 제한된 명령으로 조회한다.
  사용자 입력을 임의 원격 명령으로 실행하는 API는 제공하지 않는다.
- 선택한 GPU UUID를 실행 환경에 명시적으로 바인딩한다. 요청한 GPU 개수/종류와 관측 결과가 달라지면 전송 전에 거부한다.
  UUID는 재접속 시 번호가 바뀌어도 같은 GPU를 지정하기 위한 값이다.
- 같은 물리 서버를 여러 프로필/주소로 등록해도 중복 실행 잠금을 우회하지 못한다.
  첫 구현에서는 서버 하나당 공장 작업 하나를 실행하고 나머지는 대기시킨다.
  기존 알 수 없는 자원 잠금은 명시적 조정 없이 버리거나 우회하지 않는다.
- 가격을 조회할 수 없는 일반 서버는 운영자가 시간당 비용을 명시한다. 내부 서버 비용 0도 허용하되
  이는 클라우드 요금 조회 결과가 아니라 사용자 설정값임을 표시한다. RunPod 가격 검증은 유지한다.

## 실행과 복구

- 사용자가 지정한 안전한 절대 Linux 작업 경로 아래에 버전별 venv, 모델 캐시와 시도 폴더를 분리한다.
  일반 사용자 홈 경로를 사용할 수 있으며 서버 기본 Python이나 다른 사용자의 환경을 변경하지 않는다.
- 환경 준비는 기존 명시적 준비 동작으로만 실행하고 sudo/apt/system Python 변경을 추가하지 않는다.
  학습 시 기존 잠금 의존성·소스/엔진/CUDA 사전 검사를 그대로 적용한다.
- 실행·로그·진행률·취소·결과 회수·재조정은 원래 목적지와 시도/launch ID에 묶는다.
  설정이 다른 서버/키 지문/경로/선택 GPU로 바뀌면 과거 작업을 새 목적지로 연결하지 않는다.
- 프로필 revision과 공개 접속 설정 해시는 주소·포트·사용자·호스트 지문·원격 경로·선택 GPU 등
  목적지에 영향을 주는 공개 설정을 포함한다. 인증값/개인키 내용은 계획이나 manifest에 넣지 않는다.
- 기본 dry-run과 별도 데이터 전송/실행 승인 원칙을 유지한다. 구현 요청은 실제 BOP 접속이나 데이터 전송 승인이 아니다.

## Windows와 호환성

연결 화면에서 제공자 선택에 따라 일반 서버 필드와 RunPod 필드를 표시한다.
연결 확인, GPU 선택, 환경 확인/준비, 실행 확인 화면이 같은 공개 설정을 사용한다.
서버 프로필/설정을 바꾸면 기존 미리보기·계획·승인을 무효화한다.
과거 RunPod 설정은 제공자 필드가 없어도 RunPod로 읽으며 기존 v1 manifest/모델/데이터/MLflow 기록을 보존한다.
이후 영속 컨트롤러와 새 그래프 UI도 같은 제공자 중립 계약을 사용한다.

## 검증

실제 GPU 서버 없이 생성된 SSH 응답/로컬 격리 fixture로 인증 필수 조건, GPU 조회/선택/불일치,
서버 별칭의 잠금, 0 비용 내부 서버, 변경된 목적지/원격 경로의 복구 거부를 시험한다.
일반 서버 경로에서 RunPod API가 호출되지 않으며 기존 RunPod 흐름도 통과해야 한다.
Python 전체/Ruff, Windows UI/빌드와 native 설정 시험을 실행한다.
실제 BOP/GPU 실행과 설치본 검증은 각각 별도 실제 검증 항목으로 기록한다.

GPU 식별/선택 구현의 1차 근거:
[NVIDIA nvidia-smi](https://docs.nvidia.com/deploy/nvidia-smi/index.html),
[CUDA 환경 변수](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/environment-variables.html).
GPU UUID 조회와 CUDA_VISIBLE_DEVICES의 UUID 바인딩을 사용하며 지원하지 않는 GPU 분할 형태는 명시적으로 거부한다.
