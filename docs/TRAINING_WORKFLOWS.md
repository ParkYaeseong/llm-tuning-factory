# 학습 프로젝트와 학습 그래프 안내 · Windows 0.4.0

이 문서는 Windows 앱 0.4.0을 처음 쓰는 분을 위한 안내입니다. 빈 프로젝트를 만들고, 데이터를 가져오고, 여러 학습을
카드로 연결한 학습 그래프를 계획·승인한 뒤 백그라운드 컨트롤러로 실행하고 결과를 확인하는 순서를 따라갑니다.
설치와 업데이트는 [Windows 사용 안내](WINDOWS_APP.md), 파일 규격은 [설정·데이터 규격](CONFIGURATION.md)을 보세요.

앱 화면의 이름은 따옴표(“ ”)로 적었습니다. 화면에 보이는 글자와 같습니다.

## 한눈에 보기

| 순서 | 화면 | 하는 일 |
|---|---|---|
| 1 | “프로젝트” | 이름과 목적만 정한 빈 프로젝트를 만듭니다. |
| 2 | “데이터 가져오기” | CSV·JSON·JSONL의 열을 학습 항목에 연결해 바뀌지 않는 데이터 버전으로 등록하고 나눕니다. |
| 3 | “레시피” | 학습 단계·방법·옵션을 이름 붙여 저장합니다. |
| 4 | “학습 그래프”의 “기반 모델” | 기반 모델 버전을 고정하고 설정·토크나이저와 모듈 구조를 받습니다(가중치는 받지 않음). |
| 5 | “학습 그래프” | 학습·평가·자동 선택·병합·전체 모델 확정 카드를 직렬·병렬로 연결하고 저장합니다. |
| 6 | “계획과 승인” | 모의 실행 또는 실제 실행 계획을 만들고, 실제 실행은 두 가지 승인을 따로 합니다. |
| 7 | “실행 프로필” | 실제 실행에 쓸 RunPod Pod·GPU 서버를 등록하고 자원을 확인합니다. |
| 8 | 컨트롤러 막대 | “컨트롤러 시작”으로 백그라운드 컨트롤러를 켭니다. 앱은 자동으로 켜지 않습니다. |
| 9 | “그래프 실행” | 진행 상황, 대기 이유, 운영자 확인이 필요한 단계와 MLflow 기록을 봅니다. |

모의 실행만 해 볼 때는 RunPod·GPU 서버·MLflow 연결이 필요하지 않습니다. 다만 학습·평가 단계는 기반 모델의 설정과
토크나이저가 있어야 계획할 수 있으므로, 4단계에서 한 번은 Hugging Face에 접속할 수 있어야 합니다.

왼쪽 메뉴는 세 묶음입니다.
- 워크스페이스: “작업 공간”, “프로젝트”, “데이터”, “레시피”, “그래프 실행”, “기록 비교”
- 단일 학습: “학습 설정”, “실행 관리”(0.3.0까지의 한 작업 단위 학습 화면)
- 설정: “연결 설정”, “실행 프로필”, “튜토리얼”

“데이터 가져오기”와 “학습 그래프”는 메뉴에 따로 없고 프로젝트 화면에서 들어갑니다. Ctrl+K로 메뉴 화면을 바로 찾을 수 있습니다.

## 용어

| 용어 | 뜻 |
|---|---|
| 프로젝트 | 목적, 데이터 연결, 학습 그래프를 묶은 단위입니다. 저장할 때마다 새 버전(해시)이 생깁니다. |
| 데이터 버전 | 등록한 데이터의 바뀌지 않는 사본입니다. ID와 버전, SHA256으로 구분합니다. |
| 데이터 연결 | 프로젝트가 쓰는 데이터 버전과 역할(학습·검증·시험)입니다. 카드는 연결 ID(`train`, `validation` 등)로 데이터를 가리킵니다. |
| 레시피 | 학습 단계(SFT 등)·방법(LoRA 등)·옵션만 담은 설정입니다. 데이터, 기반 모델, GPU, 승인은 들어가지 않습니다. |
| 기반 모델 | 정확한 버전(40자리 commit)으로 고정한 Hugging Face 모델입니다. |
| 평가 기준 | 검증·시험 데이터의 고정된 샘플, 평가 방식, 토크나이저로 만든 비교 기준입니다. |
| 학습 그래프 | 학습·평가·자동 선택·병합·전체 모델 확정 카드를 연결한 실행 순서입니다. 프로젝트마다 하나입니다. |
| 자동 선택 | 같은 평가 기준의 평가 결과를 비교해 추천 모델을 정하는 단계입니다. 배포하지 않습니다. |
| 병합 | 실제로 끝난 LoRA·QLoRA 결과 2–4개를 가중치로 합치는 단계입니다. |
| 전체 모델 확정 | LoRA·QLoRA 어댑터를 기반 모델에 합쳐 전체 가중치 모델로 만드는 단계입니다. |
| 실행 프로필 | 그래프 단계를 실행할 RunPod Pod 또는 SSH GPU 서버의 이름 붙인 연결 정보입니다. |
| 백그라운드 컨트롤러 | 승인한 그래프 실행을 진행하는 프로그램입니다. 앱 창을 닫아도 계속 돕니다. PC마다 하나만 돕니다. |
| 모의 실행 | GPU를 쓰지 않고 데이터를 보내지 않는 연습 실행입니다. 결과는 실제 품질이 아닙니다. |

## 1. 빈 프로젝트 만들기

1. “작업 공간”의 “빈 프로젝트 만들기” 칸이나 “프로젝트” 화면의 “새 프로젝트” 칸에 “프로젝트 이름”(필수, 200자 이내)을
   적습니다. “작업 유형”(예: 요약, 분류)과 “목적”은 선택입니다. 예제는 필요하지 않습니다.
2. “만들기”를 누르면 프로젝트 화면이 열립니다.
3. 프로젝트 화면의 “목적과 기본 정보”에서 이름·목적과 “기본 실행 프로필”(선택)을 정합니다.
4. 바꾼 내용은 “저장”을 눌러야 반영됩니다. 저장 전에는 “저장 안 된 변경”이 표시됩니다. 계획과 실행은 저장한 버전으로만 만듭니다.

다른 창이나 다른 프로그램이 먼저 저장했다면 저장이 거부되고 “최신 버전 불러오기”와 “내 변경으로 덮어쓰기” 중 하나를
고르게 합니다. 어느 쪽이든 확인 창이 한 번 더 나오며, 내 초안은 고를 때까지 그대로 남습니다.

“단일 학습”에서 저장해 둔 설정이 있다면 “프로젝트” 화면의 “기존 학습 설정 가져오기”로 프로젝트 초안과 레시피를 만들 수
있습니다. 기존 설정 파일은 읽기만 합니다. 현재 프로젝트와 레시피를 지우는 기능은 없습니다.

## 2. 데이터 가져오기

프로젝트 화면의 “데이터 연결” 칸에서 “CSV·JSON 가져오기”를 누르면 그 프로젝트에 연결할 데이터를 가져오는 화면이 열립니다.
“데이터” 화면의 “열 연결해 가져오기”로도 들어갈 수 있습니다. 화면은 7단계입니다.

1. **원본 파일.** 이 PC의 CSV·JSON·JSONL 파일(32 MiB 이하)을 “파일 찾기”로 고르거나 경로를 입력하고 “가져오기”를 누릅니다.
   네트워크 경로(`\\서버\공유`)는 거부됩니다. 원본은 바뀌지 않는 사본으로 보관됩니다. 같은 이름의 열은 자동으로 연결됩니다.
2. **형식.** 형식은 확장자로 짐작합니다. “문자 인코딩”은 “UTF-8”, “UTF-8 (BOM)”, “CP949 · Windows 한글” 중에서 고르며,
   CP949는 CSV에서만 고를 수 있습니다. Windows Excel에서 저장한 CSV의 한글이 깨지면 CP949로 바꿔 다시 미리봅니다.
   CSV는 “구분자”(쉼표·탭·세미콜론·세로선)도 고릅니다. “데이터 종류”는 학습에 맞춰 고릅니다.

   | 데이터 종류 | 꼭 연결할 항목 | 선택 항목 |
   |---|---|---|
   | “지시·응답 · SFT” | 지시문, 정답 | 입력, 시스템 프롬프트 |
   | “텍스트 · PT” | 텍스트 | — |
   | “선호 쌍 · RM/DPO” | 지시문, 선호 응답, 비선호 응답 | 입력 |
   | “선호 라벨 · KTO” | 지시문, 정답, 선호 라벨 | 입력 |
   | “프롬프트 · PPO” | 지시문 | 입력 |

3. **열 연결.** 항목마다 원본의 열을 고릅니다. 원본 앞 5행이 함께 보입니다. 열이 500개를 넘으면 앞 500개만 고를 수 있는데,
   이 ‘앞’은 파일 순서가 아니라 열 이름의 문자 코드 순서입니다. 필요한 열이 목록에 없으면 열을 줄인 파일로 다시 가져오세요.
   KTO는 “좋은 응답으로 볼 값”과 “나쁜 응답으로 볼 값”을 함께 입력하거나 참·거짓 값이면 둘 다 비워 둡니다.
4. **미리보기.** “미리보기”를 누르면 변환 결과와 문제를 보여 줍니다. 문제는 ‘N행’(머리글을 빼고 1부터 센 원본 행), ‘헤더’,
   ‘파일’로 표시되고 50건까지 보이며 나머지는 ‘외 N건’으로 줄입니다. “원문 보기”를 펼치면 엔진의 원래 메시지가 보입니다.
   인코딩 오류에는 CP949로 바꾸라는 안내가 붙습니다. 형식이나 열 연결을 바꾸면 다시 미리보아야 합니다.
5. **등록.** 문제가 없는 미리보기에서만 “등록”이 켜집니다. “데이터 ID”(영문·숫자·`_`·`-`·`.`)와 “버전”을 정합니다.
   두 확인란은 기본으로 꺼져 있습니다.
   - ‘더미·합성 데이터입니다’: 합성 데이터로 표시합니다. 합성 데이터로 만든 결과도 이어 학습·평가·병합·전체 모델 확정 같은 다음
     실제 단계에 쓸 수 있지만, 거기서 나온 결과는 모두 계속 합성으로 표시됩니다. 합성 결과는 최상 모델로 승격하지 않고, 자동
     선택에서 고르지 않으며, MLflow 모델로 등록하지 않습니다.
   - ‘이 데이터를 선택한 GPU로 전송해도 됩니다’: 데이터 소유자가 PC 밖 전송을 승인했을 때만 켭니다. 꺼져 있으면 실제 실행에 쓸 수 없습니다.

   등록한 버전은 바뀌지 않습니다. 같은 ID와 버전에 다른 내용(확인란만 다른 경우 포함)을 등록할 수 없으니 새 버전 번호를 쓰세요.
   연습용 `tutorial_sample` ID는 이 화면에서 쓸 수 없습니다.
6. **분할(선택).** 방금 등록한 버전을 학습·검증·시험으로 나눕니다. 비율은 정수 %로 합이 100이어야 하며 기본은 80/10/10,
   “시드”는 42입니다. 같은 입력을 가진 행은 항상 같은 쪽에 들어가고, “묶음 열”을 고르면 같은 묶음 값의 행도 같은 쪽에 들어갑니다.
   같은 시드는 같은 결과를 냅니다. 출력 ID는 기본으로 `<ID>-train`, `<ID>-validation`, `<ID>-test`이며 0%인 역할은 만들지 않습니다.
   “분할 미리보기”로 역할별 행 수를 확인한 뒤 “분할 등록”을 누릅니다. 분할 결과는 원본의 합성·전송 표시를 그대로 이어받습니다.
7. **프로젝트에 연결.** 프로젝트 화면에서 들어온 경우에만 보입니다. “프로젝트에 연결”을 누르면 분할 결과를 역할별로(분할하지
   않았다면 등록한 버전을 학습 역할로) 프로젝트 초안에 더합니다. 이미 연결된 버전은 다시 더하지 않습니다.
   “프로젝트에서 저장하기”로 프로젝트 화면에 돌아가 “저장”해야 반영됩니다.

알아 둘 점:
- 학습 카드에는 학습(train) 역할 데이터만, 평가 기준에는 검증·시험 역할 데이터만 쓸 수 있습니다.
- ShareGPT 대화(`messages`·`conversations`) 파일은 이 화면에서 가져올 수 없습니다. “데이터” 화면의 기존 등록 양식에서 JSON으로
  등록한 뒤 프로젝트 화면의 “데이터 연결 추가”로 연결합니다. 그렇게 등록한 데이터는 새 화면에서 분할할 수 없습니다.
- 분할은 이 화면에서 지금 등록한 버전만 할 수 있습니다. 예전에 등록한 버전은 나눌 수 없습니다.
- 경로 검사는 글자만 봅니다. 공유 폴더를 가리키는 심볼릭 링크·정션이나 네트워크 드라이브 문자(예: `Z:`)는 알아채지 못하므로
  로컬 디스크의 파일을 고르세요.

## 3. 레시피

“레시피” 화면에서 “새 레시피”를 누르거나, “예제에서 만들기”로 예제의 학습 단계·방법·옵션만 가져온 초안을 만듭니다.
“레시피 이름”을 정하고 “학습 단계”, “학습 방법”, 학습 횟수·학습률·배치 크기 같은 옵션을 고른 뒤 “저장”합니다.

- 레시피에는 데이터, 기반 모델, GPU·Pod, 승인 정보가 들어가지 않습니다. 이것들은 그래프의 카드에서 따로 고릅니다.
- 저장할 때마다 새 버전이 생기고 이전 버전은 남습니다. 카드는 고른 레시피 버전을 고정해서 씁니다. 나중에 레시피를 고치면
  카드에 ‘고정된 이전 버전’이 표시되고 “현재 버전으로 바꾸기”로 새 버전을 쓸 수 있습니다.
- “복제”는 원본을 그대로 두고 ‘… 복사본’ 레시피를 만듭니다.
- PPO에는 OFT를 쓸 수 없고, 학습 그래프에서는 OFT 레시피를 쓸 수 없습니다.

## 4. 기반 모델: 버전 고정, 설정·토크나이저, 모듈 구조

프로젝트 화면의 “다음 단계”에서 “학습 그래프”를 누르면 그래프 화면이 열리고, 그 안에 “기반 모델” 칸이 있습니다.

1. “HF 모델 검색”에 이름을 넣고 “모델 검색”을 누르거나 “모델 ID”(예: `Qwen/Qwen2.5-0.5B-Instruct`)를 넣고 “버전 확인”을 누릅니다.
   Hugging Face의 메타데이터만 조회해 지원하는 구조인지 확인하고 정확한 버전(40자리 commit)을 고정합니다.
2. “설정·토크나이저 받기”를 누르고 안내 창에서 “받기”를 고릅니다. 그 버전의 설정(config)과 토크나이저 파일만 이 PC에 받습니다
   (파일당 64 MiB, 합계 128 MiB 이하).
3. “모듈 구조 확인”을 누르고 “확인”을 고릅니다. safetensors 파일의 머리글(header)만 범위 요청으로 읽어 모듈 구조를 기록합니다
   (합계 64 MiB 이하). `lora_target: all`(기본값)이나 Full·Freeze 학습을 모의 실행하려면 이 정보가 필요하며, 없으면 계획은
   만들어지지만 모의 실행이 그 단계에서 멈춥니다. 모듈 구조 확인은 Qwen2·Qwen3·Llama·Mistral·Gemma2·Gemma3(텍스트)·Phi-3 구조만
   지원합니다. 다른 구조는 레시피의 “LoRA 대상”을 `q_proj · v_proj`로 고르면 모의 실행할 수 있습니다.

**모델 가중치는 이 PC로 절대 받지 않습니다.** 위 두 동작은 안내 창에서 한 번 더 확인하며, 연결 설정에 저장한 HF 읽기 토큰이
있으면 그것을 씁니다. 접근 제한 모델(Llama 등)은 Hugging Face에서 이용 승인을 받아야 합니다. 실제 학습 때 가중치는 GPU 쪽
(Pod·서버)이 내려받습니다.

## 5. 학습 그래프 편집

그래프가 비어 있으면 시작 모양 네 가지 중 하나를 고를 수 있습니다.

| 시작 모양 | 만들어지는 카드 |
|---|---|
| “단일 학습” | 학습 카드 하나 |
| “직렬 추가 학습” | 학습 → 그 결과로 이어서 학습 |
| “병렬 비교” | 학습 두 개, 각각의 평가, 두 평가를 비교하는 자동 선택 |
| “병렬 비교 후 병합” | 학습 두 개, 둘의 병합(50/50), 세 평가(두 학습과 병합), 자동 선택 |

카드를 직접 더할 때는 카드를 하나 고른 뒤 도구 막대를 씁니다.
- **직렬:** “다음 단계 추가”는 고른 카드 뒤에 이어지는 카드를 더합니다. 단계 종류를 고르는 목록이 열리고, 이어 붙일 수 없는
  종류는 이유와 함께 꺼져 있습니다.
- **병렬:** “나란히 추가”는 고른 카드와 같은 종류·같은 입력의 카드를 옆에 더합니다.
- “새 학습 단계”는 아무것과도 연결하지 않은 학습 카드를, “단계 삭제”는 카드와 그 카드로 들어오는 연결을 지웁니다.

카드 목록은 Tab 한 번으로 들어가며 위아래 화살표·Home·End로 옮기고 Enter로 고릅니다. 오른쪽 미리보기는 카드와 같은
초안으로 그립니다. 고른 카드의 입력 칸에서 이름, 레시피, 입력 모델, 데이터, 실행 프로필을 정합니다.

| 카드 | 정하는 것 | 규칙 |
|---|---|---|
| 학습 | 레시피, 입력 모델(기반 모델 또는 앞 학습의 결과), 학습 데이터, PPO면 보상 모델, 실행 프로필 | 학습 역할 데이터만. 초기화(새 어댑터·전체 가중치·어댑터 이어 학습)는 레시피의 학습 방법으로 정해집니다. |
| 평가 | 평가할 모델, 평가 기준(“새 평가 기준”으로 만들 수 있음), 실행 프로필 | 평가 기준은 검증·시험 데이터만 씁니다. |
| 자동 선택 | 비교할 평가, 선택 지표, 방향, 기준값(선택), ‘일부 평가만 성공해도 선택’과 최소 성공 수(2 이상), 병합 회귀 허용치(기본 0) | 같은 평가 기준의 평가끼리만 비교하며, 그 평가 기준은 검증(validation) 데이터여야 합니다. 시험(test) 데이터 평가는 선택에 쓰지 않습니다. 같은 모델을 두 번 평가해 비교할 수 없고(앞 자동 선택이 고를 수 있는 모델 포함), 병합 모델의 평가는 하나까지이며 그 옆에 원본 모델의 평가가 있어야 합니다. 어기면 “계획 확인”에서 거부됩니다. GPU를 쓰지 않습니다. |
| 병합 | 병합할 모델 2–4개와 가중치(%) | LoRA·QLoRA 어댑터만 합칩니다: 학습 결과, 다른 병합의 결과, 또는 그런 어댑터를 고를 수 있는 자동 선택의 결과. 전체 모델 확정 결과는 합칠 수 없고, 같은 모델을 두 번 합칠 수 없습니다(자동 선택을 거쳐도). 가중치 합 정확히 100%, 합친 rank(안쪽 병합 포함) 256 이하. 어기면 “계획 확인”에서 거부됩니다. 실제로 끝난 결과만 합칩니다. |
| 전체 모델 확정 | 확정할 모델 | LoRA·QLoRA 결과만. 학습 방법이 바뀌는 다음 학습 앞에 꼭 넣어야 합니다. |

그 밖의 규칙:
- 카드는 최대 64개, 연결은 최대 256개입니다. 순환 연결은 만들 수 없습니다.
- 평가 결과는 모델 입력으로 쓸 수 없고, 자동 선택에는 평가 결과만 연결합니다.
- PPO 학습은 다른 학습과 결과를 주고받을 수 없고 보상 모델 연결이 필요합니다. OFT 결과는 다음 단계로 넘길 수 없습니다.
- 카드에서 실행 프로필을 여러 개 고르면 비어 있는 곳에서 실행합니다. 프로필 하나만 고른 카드끼리는 같은 자원을 순서대로
  기다립니다(미리보기의 점선 테두리, 카드의 ‘대기’).
- 자동 선택의 병합 회귀 허용치가 0이면 병합 모델이 원본 최상 모델보다 낮을 때 원본을 유지합니다. 병합 모델의 평가를 선택에 쓸 수
  없을 때(점수 없음, NaN, 기준값 미달, 합성)도 원본 최상 모델을 유지합니다.
- 병합이나 병합 모델의 평가가 실패했을 때:
  - ‘일부 평가만 성공해도 선택’이 꺼져 있으면 자동 선택은 ‘앞 단계 실패로 중단’됩니다. 원본을 평가했더라도 아무 모델도 고르지
    않으며 실행은 ‘실패’로 끝납니다.
  - 켜져 있으면 최소 성공 수 이상의 원본 평가가 성공했을 때 원본 최상 모델을 고르고, 못 미치면 고른 모델 없이 끝납니다. 실패한
    단계가 있으므로 실행은 이때도 ‘실패’로 끝납니다.
- 자동 선택은 추천 결과를 확정할 뿐 배포하지 않습니다. 정확 일치·문자 F1 같은 텍스트 정답 일치 지표는 의미적 품질 점수가
  아니고, JSON 형식 유효성은 품질 지표가 아닙니다.

“실행 설정”에서는 그래프 전체의 “최대 동시 실행”(1–64, 기본 1), “최대 총비용 (USD)”(기본 100, 재시도를 포함한 계획 상한),
“재시도 횟수”(1–5, 기본 1), “재시도 간격 (초)”(0–3600, 기본 0)를 정합니다.

“저장”을 누르면 그래프를 저장하고 저장한 버전을 바로 검사합니다. 카드별 문제는 카드에, 데이터 연결 문제는 “저장한 그래프
검사 결과”에 보입니다.

### 평가 기준 만들기

평가 카드의 “새 평가 기준”을 누르면 “평가 데이터”(검증·시험 역할), “평가 방식”, “샘플 수”(앞에서부터 고정), “답변 최대 토큰”,
“시드”, “정밀도”, 토크나이저로 쓸 “기반 모델 (토크나이저)”를 고르는 칸이 열립니다. “평가 기준 저장”을 누르면 그 평가 카드에
연결됩니다(그래프는 따로 저장해야 합니다). 평가 방식마다 고를 수 있는 지표가 다르며, ‘학습 완료 확인’ 방식은 지표가 없어
자동 선택에 쓸 수 없습니다.

## 6. 계획과 승인

그래프 화면 아래의 “계획과 승인” 칸에서 계획을 만듭니다. 계획은 저장한 그래프 버전으로만 만들며, 저장 전이면 “계획 확인”이
꺼집니다.

**계획 종류.**
- “모의 실행 계획 · 기본”: GPU를 쓰지 않고 데이터를 보내지 않습니다. MLflow에도 기록하지 않습니다. 비용 계산을 위해
  “계획용 추정 자원”(이름 `estimate-…`, GPU 종류·수, 시간당 총 요금)을 “추정 자원 추가”로 넣고 카드의 실행 프로필에서 고릅니다.
  기본 요금은 없으니 견적이나 요금표의 시간당 총액을 입력하세요.
- “실제 실행 계획”: 승인하면 실행 자원에서 GPU 요금이 발생하고 데이터를 보냅니다. 다음이 모두 필요합니다.
  - 카드마다 실제 “실행 프로필”(추정 자원은 쓸 수 없음). RunPod 프로필은 API 키가 저장되어 있어야 합니다.
  - 각 실행 프로필을 **1시간 이내에** “자원 확인”한 기록(7장). 오래되면 계획이 거부됩니다.
  - “연결 설정”에 저장한 MLflow 서버 주소
  - “GPU 전송 허용”으로 등록한 데이터. 연습용 `tutorial_sample`은 쓸 수 없습니다.

**단계별 최대 실행 시간.** 학습·평가·병합·확정 카드마다 분 단위로 정합니다(기본 60분, 1–10080분). 자동 선택은 GPU를
쓰지 않아 시간 제한이 없습니다. 바뀐 계획 입력은 “계획 확인” 때 이 PC의 프로젝트별 기록에 저장됩니다.

**계획 확인.** “계획 확인”을 누르면 계획 카드에 ‘최대 추정 비용’, ‘최대 소요 시간’, ‘최대 동시 GPU’, ‘계획 해시’와 단계별
실행 위치가 보입니다. 같은 실행 자원을 기다리는 단계에는 ‘대기 후 순차 실행’이 붙습니다. 경고는 실행을 막지 않습니다.
계획 뒤에 그래프·계획 입력·실행 프로필·연결 설정·레시피를 바꾸면 계획 카드가 ‘변경되어 다시 계획해야 합니다’로 바뀌고,
“다시 계획”을 눌러야 합니다. 승인하지 않은 계획은 실행되지 않습니다.

**승인.** “계획 승인·실행…”을 누르면 승인 창이 열립니다.
- 모의 실행: 창 제목은 “모의 실행 등록”이며 확인란 없이 “모의 실행 등록”으로 등록합니다.
- 실제 실행: 창 제목은 “실행 승인”입니다. 실행 위치(프로필, GPU, 시간당 총 요금, 요금 출처), 데이터(ID, 버전, SHA256, 합성 여부,
  전송 허용), MLflow 기록 위치, 최대 추정 비용·소요 시간·동시 GPU·단계별 최대 시도를 확인한 뒤 두 확인란을 **각각** 체크해야
  “승인하고 실행 등록”이 켜집니다.
  - ‘실행 승인’: 위 실행 자원에서 학습·평가·병합을 실행하고 최대 추정 비용까지 GPU 요금이 발생하는 것을 승인합니다.
  - ‘데이터 전송 승인’: 위 데이터를 위 실행 자원으로 보내는 것을 승인합니다.

최대 추정 비용은 재시도를 포함한 추정치입니다. **제공자의 청구 상한이 아니며** 저장·대기 비용은 따로 듭니다. 기존 Pod는
그래프가 끝나도 계속 과금될 수 있습니다.

같은 계획은 한 번만 실행합니다. 앱은 승인 창을 열기 전에 기존 실행을 확인해, 이미 등록한 계획이면 승인 창 대신 등록된
실행을 알려 주고 “실행 보기”로 그 실행을 엽니다. 실행 목록을 읽지 못하면 승인하지 않습니다. 엔진도 이미 등록한 계획을 다시
등록하지 않고 기존 실행을 알려 주며, 그 실행을 취소한 뒤에도 마찬가지입니다.

같은 그래프를 다시 실행하려면 새 계획이 나와야 합니다.
- 실제 실행 계획과 실행 프로필만 쓰는 모의 실행 계획은 저장된 자원 확인 기록으로 계산하므로, 입력이 같으면 같은 계획(같은
  계획 해시)이 나오고 앱은 기존 실행을 보여 줍니다. 입력을 하나 바꾸세요. 그 실행 프로필의 “자원 확인”을 다시 하는 것으로 충분합니다.
- 계획용 추정 자원을 쓰는 모의 실행 계획은 “계획 확인”을 누를 때마다 새 계획이 됩니다.

등록에 성공하면 “그래프 실행” 화면이 열립니다. **등록해도 컨트롤러는 자동으로 시작하지 않습니다.**

## 7. 실행 프로필(실제 실행에만 필요)

“설정 › 실행 프로필” 화면에서 “새 실행 프로필”을 눌러 실제 실행에 쓸 자원을 등록합니다. “연결 설정”의 단일 학습 연결과는
따로 보관합니다. 앱은 Pod나 서버를 시작·종료·삭제하지 않습니다.

공통 칸은 “프로필 ID”(영문·숫자·`_`·`-`·`.`, 64자 이내, 저장 후 바꿀 수 없음), “연결 대상”(저장 후 바꿀 수 없음), “이름”입니다.

**RunPod Pod.** “Pod ID”, “SSH 서버 지문”(관리자가 신뢰할 수 있는 경로로 확인한 `SHA256:` 값), “SSH 개인키 파일”, “RunPod API 키”.
- API 키는 이 프로필 전용으로 Windows 자격 증명 저장소에 보관하며 화면에 다시 보여 주지 않습니다. 목록에는 ‘API 키 보안 저장됨’
  또는 ‘API 키 없음’만 보입니다. 키 칸을 비우고 저장하면 저장된 키를 그대로 씁니다.
- 연결 설정에 RunPod 키가 저장되어 있으면 그 키를 이 프로필에도 저장하는 확인란이 보입니다(키를 입력하지 않을 때만).

**GPU 서버(SSH).** “서버 주소”, “SSH 포트”, “접속 계정”, “SSH 서버 지문”, “작업 폴더 · 절대 경로”, “SSH 개인키 파일”,
“시간당 비용 (USD) · 서버 전체”(직접 입력하는 값, 내부 서버는 0). 연결 정보를 먼저 저장한 뒤 “GPU 목록 확인”으로 서버의
GPU를 읽고(읽기 전용, `nvidia-smi`), 사용할 GPU(최대 8개)를 체크해 다시 저장합니다. 서버 요구 조건은
[Windows 사용 안내](WINDOWS_APP.md)의 GPU 서버 항목과 같습니다.

**장비 하나에 프로필 하나.** 같은 서버를 다른 주소로 등록한 GPU 서버 프로필끼리는 같은 장비로 알아봅니다. 하지만 한 장비를
RunPod 프로필과 GPU 서버 프로필로 함께 등록하면 서로 다른 실행 대상으로 계산하므로, 계획의 ‘대기 후 순차 실행’ 표시와
‘최대 동시 GPU’가 둘을 따로 셉니다. 이 PC의 앱에서는 RunPod 작업과 GPU 서버 작업이 서로 끝나기를 기다리지만, 다른 상태 폴더나
다른 PC에서 쓰면 앱이 동시 사용을 막지 못합니다. 실제 장비 하나는 프로필 하나로만 등록하세요.

**키 파일 경로.** SSH 개인키는 이 PC의 **전체 경로**(예: `C:\Users\이름\.ssh\id_ed25519`)로 입력하거나 “파일 찾기”로 고릅니다.
상대 경로·네트워크 경로, `NUL`·`CON`·`COM1` 같은 장치 이름이 들어간 경로, 드라이브 뒤의 `:`(대체 스트림), 앞뒤 공백이나 끝의
마침표, 붙여 넣은 키 내용, PuTTY `.ppk`는 저장할 때 거부됩니다. 개인키는 OpenSSH 형식의 암호 없는 파일이어야
하며 원래 위치에 남습니다. 키 파일을 옮기거나 경로를 바꾸면 연결 정보가 바뀐 것으로 보므로 다시 계획해야 하고, 예전 경로로
시작한 실행의 결과 회수는 거부될 수 있습니다.

**자원 확인과 1시간 규칙.** 목록의 “자원 확인”은 RunPod API로 Pod 상태를 읽거나 저장된 SSH 연결로 서버의 GPU와 실행 환경을
읽기만 합니다(Pod·서버를 바꾸거나 데이터를 보내지 않음). 확인한 GPU와 요금은 이 PC에 기록되고 ‘마지막 자원 확인’ 열에
‘N분 전 확인’, GPU × 수, 시간당 요금과 출처가 보입니다. **실제 실행 계획에는 1시간 이내의 확인이 필요합니다.** 1시간이
지났거나 확인 후 프로필을 고쳤다면 다시 확인하세요. 모의 실행 계획은 계획용 추정 자원만 쓰면 확인이 필요 없고, 실행 프로필을
고르면 오래된 것이라도 확인 기록이 하나는 있어야 합니다(확인 당시의 자원으로 계산).

**수정과 삭제.** 실행 중이거나 결과 확인이 끝나지 않은 작업이 쓰는 프로필은 고치거나 지울 수 없습니다. 고친 뒤
‘이 변경 후 다시 계획해야 하는 실행’이 보이면 그 실행은 다시 계획해야 합니다. 삭제하면 그 프로필의 API 키도 함께 지웁니다.

주의: “연결 설정”의 “저장된 인증값 삭제”는 연결 설정의 인증값과 함께 **모든 실행 프로필의 RunPod API 키도 지웁니다.**

## 8. 백그라운드 컨트롤러

승인한 그래프 실행은 백그라운드 컨트롤러가 진행합니다. 컨트롤러 막대는 “실행 프로필”과 “그래프 실행” 화면 위쪽에 있습니다.

- **시작.** “컨트롤러 시작”을 누르면 켜지고 상태가 “동작 중”(마지막 신호 N초 전)이 됩니다. **앱은 컨트롤러를 자동으로 시작하지
  않습니다.** 앱을 다시 열거나 실행을 등록해도 저절로 켜지지 않으므로 꺼져 있으면 직접 누릅니다. PC를 다시 켠 뒤에도 같습니다.
  이미 돌고 있으면 그대로 둡니다.
- **창을 닫아도 계속 돕니다.** 앱 창을 닫아도 컨트롤러는 계속 실행을 진행합니다. 다시 앱을 열면 막대가 “동작 중”을 보여 줍니다.
  PC가 절전·종료되면 멈추며, 다시 켠 뒤 막대에 “연결 끊김”이 보이면 컨트롤러를 다시 시작하세요.
- **정지.** “컨트롤러 정지” → “정지 요청”을 누르면 상태가 ‘정지 요청됨 · 진행 중 단계가 끝나면 정지합니다’로 바뀝니다.
  진행 중인 단계가 끝날 때까지 기다리므로 **학습 중이면 몇 시간이 걸릴 수 있습니다.** 즉시 멈추는 버튼은 없습니다. 상태가 “정지”가
  되면 끝난 것입니다.
- **설정을 바꾼 뒤에는 다시 시작.** 컨트롤러는 시작할 때의 실행 프로필, RunPod 키, MLflow 설정을 계속 씁니다. 실행 프로필을 고치거나
  RunPod 키·MLflow 인증값을 저장·변경하면 다시 시작해야 새 값을 씁니다. 순서는 일시정지 → 진행 중 단계 완료 대기(또는 컨트롤러
  정지) → 설정 저장 → 컨트롤러 시작입니다. 프로필이나 MLflow 주소가 바뀌면 막대가 알려 주지만, **다른 변경 없이 키만 바꾼 경우는
  알아채지 못하므로** 직접 다시 시작하세요.
- **PC마다 하나.** 한 PC(앱 데이터 폴더)에는 컨트롤러가 하나만 돕니다. 서로 다른 PC는 GPU 잠금과 비용 한도를 공유하지 않습니다.
- **업데이트·제거 전 정지.** 설치 프로그램을 실행하기 전에 컨트롤러를 정지하고 “정지”가 된 뒤 앱을 닫으세요
  ([Windows 사용 안내](WINDOWS_APP.md)의 업데이트·제거).
- 앱 데이터 폴더가 네트워크 경로(리디렉션된 AppData)에 있으면 컨트롤러를 시작할 수 없습니다. 단일 학습 기능은 계속 쓸 수 있습니다.

## 9. 그래프 실행 화면

“그래프 실행”의 “실행 목록”에서 실행을 열면 상태(실행 중·일시정지·완료·실패·취소), 모의/실제, 계획 해시, 승인 예산과 예약된
비용, MLflow 기록 상태, 단계 표(상태, 시도, 실행 위치, 진행 정보, 기록, 결과)가 보입니다. 화면은 열려 있는 동안 자동으로 새로
읽습니다(목록 10초, 연 실행 3초, 컨트롤러 5초). 창을 최소화하면 읽기를 멈추고 다시 보이면 바로 읽습니다.

**대기 이유.** 기다리는 단계의 ‘진행 정보’에 이유가 한국어로 보입니다. 예:
- 같은 실행 자원의 다른 단계가 끝나기를 기다리는 중(한 Pod·서버에는 한 번에 한 작업만 돌며, 같은 서버를 다른 주소로 등록해도
  같은 잠금을 씁니다)
- 앞 단계가 끝나기를, 또는 앞 단계의 MLflow 기록이 저장되기를 기다리는 중
- 최대 동시 실행 수, 다시 시도 간격, 다른 연결 대상(RunPod 등)의 잠금
- 실행 자원의 실제 GPU나 가격이 승인한 계획과 다르거나 실행 프로필이 바뀜 → 다시 계획하세요
- 승인 예산 소진 → 더 큰 예산으로 다시 계획하세요

번역하지 못한 이유는 영어 그대로 보이며 “원문 보기”로 엔진의 원래 문장을 볼 수 있습니다.

**결과 대기와 운영자 확인 필요.**
- “결과 대기”: 원격 실행의 결과가 늦게 도착할 수 있는 상태입니다. 그 실행의 시간 제한에 10분을 더한 시각까지는 다시 실행하지
  않고 실행 자원 잠금도 그대로 둡니다. 할 일은 없습니다. 기다리세요.
- “운영자 확인 필요”: 원격 실행이 멈췄는지 앱이 알 수 없는 상태입니다(예: 시간 제한이 지나도 결과가 없음, 실행 요청의 응답을
  잃음). 잠금을 유지한 채 기다립니다. 결과 기록 실패나 작업 기록 검사 실패처럼 데스크톱에서 풀 수 없는 경우도 있으며, 그때는
  화면 안내대로 운영자가 `factory status`로 상태를 확인하고 복구해야 합니다.

**실행 잠금 해제.** 데스크톱에서 풀 수 있는 “운영자 확인 필요” 단계에는 “실행 잠금 해제” 버튼이 있습니다.
1. 먼저 RunPod 콘솔이나 서버의 프로세스 목록에서 그 작업·시도의 실행이 **멈춘 것을 직접 확인**합니다.
2. 버튼을 누르면 창에 작업 ID와 시도 ID, 위험(아직 돌고 있으면 같은 GPU에 다른 단계가 배정되어 두 작업이 함께 돌거나 늦은 결과가
   버려짐)과 효과(결과가 없으면 그 단계는 실패로, 취소를 요청한 실행이면 취소로 기록되고 다시 실행하지 않음)가 보입니다.
3. 단계 이름을 그대로 입력하고 ‘원격 서버/Pod에서 해당 실행이 멈춘 것을 확인했습니다’를 체크해야 “잠금 해제”가 켜집니다.
4. 해제 후 컨트롤러가 다음 확인 때 그 시도를 정리합니다. 컨트롤러가 꺼져 있으면 시작하세요. 결과가 필요하면 다시 계획해 새로
   실행합니다.

창이 열린 사이 실행 상태가 바뀌면 버튼이 꺼집니다. 소스로 설치한 CLI가 있다면 같은 일을 명령줄로 할 수 있습니다(설치형 앱에는
`factory` 명령이 들어 있지 않습니다). 창의 ‘명령줄로 해제하기(대안)’에 ID가 채워진 명령이 있습니다.

```powershell
uv run factory --state-dir "$env:APPDATA\kr.kbiofoundry.tuningfactory\state" status --job-id JOB_ID
uv run factory --state-dir "$env:APPDATA\kr.kbiofoundry.tuningfactory\state" release-lock JOB_ID ATTEMPT_ID --confirm-execution-stopped
```

**일시정지·다시 진행·취소.** “일시정지”는 새 단계를 시작하지 않고 이미 실행 중인 단계는 끝날 때까지 둡니다. “다시 진행”은
컨트롤러가 다음 확인 때 대기 단계를 배정합니다. “취소”는 진행 중인 단계에 취소를 요청하며 원격 종료가 확인될 때까지 자원을
해제하지 않습니다. 취소한 실행은 다시 진행할 수 없습니다.

**결과 읽기.** 평가 결과의 지표 옆에 텍스트 정답 일치 지표나 형식 지표라는 안내가 붙습니다. 자동 선택 결과는 ‘최상 모델’,
‘병합 모델 선택’, ‘원본 최상 모델 유지’ 또는 기준을 통과한 후보가 없다는 문장으로 보입니다. 모의 실행 결과에는 ‘모의 결과는
실제 품질이 아닙니다’가 붙고 최상 모델을 정하지 않습니다. 합성 후보(합성 데이터에서 나온 모델의 평가, 또는 합성 데이터로 만든
평가 기준의 평가)도 고르지 않습니다.
- ‘일부 평가만 성공해도 선택’이 꺼진 자동 선택은 원본 후보 중 하나라도 합성이면 고른 모델 없이 끝납니다.
- 이 확인란을 켜면 합성이 아닌 원본만 고를 수 있고, 그런 후보가 최소 성공 수 이상일 때만 고릅니다.
- 병합 모델 후보가 합성이면 원본 최상 모델을 유지합니다.

## 10. MLflow 기록

실제 실행은 계획 때 고정한 MLflow 서버에 그래프 실행 → 단계 → 시도 순서의 계층으로 기록하고, 시도 결과 파일, 자격이 있는 모델의
등록, 그래프 요약을 남깁니다. 모의 실행은 MLflow에 기록하지 않습니다.

기록은 이 PC의 기록 대기열(outbox)을 거쳐 보내므로 MLflow가 잠시 끊겨도 학습 결과는 잃지 않습니다. 상태는 ‘기록 전’, ‘기록 대기’,
‘기록 재시도’, ‘기록됨’, ‘기록 확인 필요’, ‘기록 실패’, ‘등록됨’으로 보입니다. 실패했거나 결과가 불확실한 기록은 “MLflow 기록 문제”
칸에 나오며, MLflow에 다시 연결되면 “기록 다시 시도”로 다시 보냅니다(re-arm). 기록한 뒤 로컬 결과 파일이 바뀌었다는 경고가
나오면 다시 시도해도 고칠 수 없으니 원래 파일을 되돌리거나 새 실행에서 그 단계를 다시 실행하세요.

인증 방식(OIDC·토큰·인증 없음)과 HTTPS 규칙은 단일 학습과 같습니다. 인증값이 있으면 HTTPS 주소만 허용하고, “인증 없음”은
신뢰할 수 있는 로컬·내부망에서만 쓰세요. 그래프 컨트롤러의 TLS 동작은 단일 학습과 다릅니다(아래 ‘알려진 한계’).

## 11. 운영 원칙

- **빌린 자원은 켜거나 끄지 않습니다.** 앱과 CLI는 기존 RunPod Pod와 GPU 서버를 생성·시작·정지·삭제하지 않습니다. 실행이 끝난 뒤
  Pod를 멈추는 것은 담당자의 몫이며, 멈추지 않으면 계속 과금될 수 있습니다.
- **합성·모의 결과는 승격하거나 등록하지 않습니다.** 합성 데이터로 만든 결과는 다음 실제 단계(이어 학습·평가·병합·전체 모델
  확정)에 쓸 수 있지만, 거기서 나온 결과까지 모두 합성으로 남아 최상 모델로 확정하지 않고, 자동 선택에서 고르지 않으며, MLflow
  모델 레지스트리에 등록하지 않습니다. 모의 실행 결과는 실제 실행에 쓰지 않으며 확정하거나 등록하지도 않습니다.
- **같은 계획은 두 번 등록하지 않습니다.** 앱과 CLI 모두 같은 계획 해시의 실행이 이미 있으면 다른 요청 ID로 보낸 등록을
  거부하고(`plan_submitted`) 기존 실행을 알려 줍니다. 그 실행을 취소한 뒤에도 같습니다. 같은 요청 ID로 다시 보내면 같은 실행을
  돌려줍니다. 앱은 요청 ID로 `plan-<PLAN_SHA256>`(`plan-` 뒤에 계획 해시)을 쓰므로 CLI에서도 `--request-id plan-<PLAN_SHA256>`을
  쓰면 앱과 CLI가 서로의 등록을 같은 요청으로 알아봅니다. 다시 실행하려면 입력을 바꿔 새 계획을 만드세요(6장).
- **모의 병합은 거부합니다.** 병합은 실제로 끝난 LoRA·QLoRA 결과만 합칩니다. 모의 실행 계획에서는 병합 단계에서 멈춥니다.
- **끝난 학습은 다시 하지 않습니다.** 컨트롤러가 멈췄다 다시 시작해도 끝난 단계를 다시 학습하지 않고, 진행 중이던 시도는 원격
  결과를 다시 확인해 이어받습니다. 확인할 수 없으면 ‘운영자 확인 필요’로 기다립니다.
- **인증값은 기록하지 않습니다.** RunPod 키와 MLflow 인증값은 Windows 자격 증명 저장소(CLI는 로컬 파일·환경 변수)에만 있고,
  계획·실행 기록·영수증에는 ID와 해시만 남습니다.

## 12. CLI로 같은 작업하기

소스로 설치한 CLI(`uv run factory …`)는 앱과 같은 상태 폴더를 다룰 수 있습니다. 앱의 상태 폴더는
`%APPDATA%\kr.kbiofoundry.tuningfactory\state`이며 `--state-dir`로 지정합니다(전역 옵션이므로 명령 앞에 둡니다).
프로젝트·레시피·데이터·기반 모델 준비를 만드는 CLI 명령은 없으므로 이것들은 앱에서 만듭니다.

| 앱 동작 | CLI |
|---|---|
| 프로젝트 목록 | `factory project-list` |
| 그래프 저장 후 검사 | `factory graph-validate PROJECT_ID [--revision REVISION]` |
| 자원 확인 | `factory executor-profile-inspect PROFILE_ID --executor-profiles FILE` |
| 계획 확인(모의 실행) | `factory graph-plan PROJECT_ID --request FILE` |
| 계획 확인(실제 실행) | `factory graph-plan PROJECT_ID --request FILE --executor-profiles FILE --real` |
| 모의 실행 등록 | `factory graph-submit PLAN_SHA256 --request-id plan-<PLAN_SHA256>` |
| 실행 승인과 데이터 전송 승인 | `factory graph-submit PLAN_SHA256 --request-id plan-<PLAN_SHA256> --approve-execution --approve-data-transfer --executor-profiles FILE` |
| 그래프 실행 화면 | `factory graph-status [RUN_ID]` |
| 일시정지·다시 진행·취소 | `factory graph-pause RUN_ID`, `factory graph-resume RUN_ID`, `factory graph-cancel RUN_ID` |
| 기록 다시 시도 | `factory graph-rearm-tracking EVENT_ID` |
| 실행 잠금 해제 | `factory status --job-id JOB_ID`, `factory release-lock JOB_ID ATTEMPT_ID --confirm-execution-stopped` |
| 컨트롤러 시작·정지 | `factory graph-work` (앞에서 실행, Ctrl+C 한 번은 정지 요청, 두 번은 즉시 종료) |

- 표의 대문자 이름(`PLAN_SHA256` 등)은 실제 값으로 바꿔 입력합니다. 요청 ID `plan-<PLAN_SHA256>`은 `plan-` 뒤에 같은 계획 해시를
  붙인 값입니다(꺾쇠는 입력하지 않음). 예: 계획 해시가 `3f2a…`이면 `--request-id plan-3f2a…`.
- `graph-work`는 같은 컨트롤러를 터미널 앞에서 실행합니다. `--approve-execution-and-transfer`가 없으면 모의 실행만 진행하고 실제
  실행은 기다립니다. 실제 실행에는 `--approve-execution-and-transfer --executor-profiles FILE`이 필요하며, 이때만 프로필의 RunPod 키와
  MLflow 인증값을 읽습니다. `--tick-seconds`(기본 5초)로 확인 간격을, `--max-ticks`로 확인 횟수 상한을 정할 수 있습니다. 종료 코드는
  0(정지 완료), 1(소유권 상실·오류), 2(시작 전 거부), 3(다른 컨트롤러 실행 중), 4(MLflow 설정 거부), 130(Ctrl+C 두 번)입니다.
- **`graph-work`에는 앱의 상태 폴더를 지정하세요.** 앱의 컨트롤러가 돌고 있을 때 시작하지 않는(종료 코드 3) 것은 `--state-dir`로
  앱의 상태 폴더를 가리킬 때뿐입니다. `--state-dir`을 빼면 CLI 기본값 `./state`에 컨트롤러가 따로 뜹니다. GPU 잠금은 상태 폴더마다
  따로 있으므로, 그 컨트롤러는 앱이 쓰고 있는 같은 빌린 Pod·서버에 작업을 동시에 보낼 수 있습니다.
- Ctrl+C를 두 번 눌러 즉시 끝내면 60초 동안 다시 시작할 수 없고, 진행 중이던 단계는 `release-lock`이 필요할 수 있습니다.
- 실제 계획을 `graph-submit`할 때는 계획할 때와 같은 `--executor-profiles` 파일과 같은 MLflow 환경(`.env` 등)을 써야 합니다.
  다르면 계획 이후 바뀐 것으로 보고 거부합니다(`plan_stale`).
- `graph-plan`의 `--request` 파일에는 단계별 `node_resources`(`node_id`, `timeout_seconds` 60–604800, `runtime_profile`
  `primary`·`ppo`)와 모의 실행용 `estimates`를 적습니다. `project_id`와 `simulation`은 넣지 않습니다(`--real`로만 실제 계획).
- `--executor-profiles` 파일은 앱의 실행 프로필과 같은 공개 항목만 담습니다. RunPod 키는 프로필마다 별도 인증 파일
  (`credential_file`)을 가리키거나, 없으면 `.env`·환경 변수의 `RUNPOD_API_KEY`를 씁니다. 형식은
  [설정·데이터 규격](CONFIGURATION.md)의 CLI profiles file을 보세요.
- 모든 명령은 JSON을 출력하며 거부 이유를 경로와 함께 보여 줍니다. 값(키 등)은 출력하지 않습니다.

## 13. 알려진 한계

- **컨트롤러 감시 장치 없음.** 실행 자원에 연결한 뒤의 작업(결과 회수, 재조정, 환경 확인)은 SSH·HTTP 연결 계층의 제한 시간에만
  기댑니다. 그 안에서 작업이 멈추면 컨트롤러는 “동작 중”으로 보이면서 다음 확인을 하지 못할 수 있습니다. 마지막 신호는 새로운데
  오래 진행이 없으면 컨트롤러를 정지했다가 다시 시작하세요.
- **밀려난 컨트롤러가 잠시 남음.** 절전 뒤처럼 다른 컨트롤러가 소유권을 넘겨받으면, 이전 컨트롤러 프로세스는 진행 중이던 요청이 돌아올
  때까지 남아 있다가 끝납니다. 그 사이 새 작업은 하지 않습니다.
- **모델 등록 상태.** MLflow가 처리 중(PENDING)으로 받은 모델 버전을 나중에 `FAILED_REGISTRATION`으로 바꿔도 앱은 ‘등록됨’으로
  보여 줍니다. 중요한 등록은 MLflow에서 직접 확인하세요.
- **환경의 인증 파일.** 컨트롤러는 시작할 때 RunPod·MLflow·클라우드 인증 환경 변수를 지우지만, 파일로 된 인증 정보(AWS 공유 인증
  파일, Azure CLI 캐시, gcloud 기본 인증 등)는 읽을 수 있는 상태로 남습니다.
- **리디렉션된 AppData.** 앱 데이터 폴더가 `\\서버\…` 같은 네트워크 경로에 있으면 컨트롤러를 시작할 수 없습니다. 이 PC는 리디렉션
  환경이 아니어서 실제로 시험하지 않았습니다.
- **로컬 파일 검사의 범위.** 데이터·키 파일 경로 검사는 글자만 보므로 공유 폴더로 가는 링크·정션이나 네트워크 드라이브 문자는
  알아채지 못합니다.
- **그래프 컨트롤러의 TLS 동작 변경.** 앱과 `graph-work`의 그래프 컨트롤러는 `MLFLOW_TRACKING_INSECURE_TLS`와 mTLS 클라이언트 인증서
  (`MLFLOW_TRACKING_CLIENT_CERT_PATH`)를 지우고 시작합니다. 자체 서명 인증서를 쓰는 MLflow 서버는
  `MLFLOW_TRACKING_SERVER_CERT_PATH`(CA 묶음)로 지정하세요(`REQUESTS_CA_BUNDLE`, `SSL_CERT_FILE`도 유지됩니다). mTLS MLflow는
  그래프 실행에서 지원하지 않습니다. 단일 학습의 `work`는 이전처럼 두 값을 씁니다.
- **ShareGPT 데이터 분할 불가.** ShareGPT 대화 데이터는 기존 등록 양식으로만 등록되며 새 화면에서 나눌 수 없습니다. 미리 나눈 파일을
  각각 등록하세요.
- **열 500개 선택 한도는 이름순.** 열이 500개를 넘으면 열 이름의 문자 코드 순서로 앞 500개만 고를 수 있습니다.
- **모의 병합.** 모의 실행 계획에서 병합 단계와 그 뒤 단계는 진행하지 않습니다.
- 대기 이유는 엔진의 영어 문장 앞부분으로 번역하므로 번역되지 않은 문장은 영어로 보입니다.
- 계획 입력 중 추정 자원과 최대 실행 시간은 저장되지만, 저장하지 않은 그래프 초안과 받아 둔 계획은 창을 닫으면 사라집니다.
- 여러 PC 사이의 실행 대기열·GPU 잠금은 공유되지 않습니다.
